================================================================================
PAYMENT FLOW
================================================================================

1. User clicks "Rent Property"
   ↓
2. POST /payment/student-property/{id}/initiate/
   ↓
3. Creates Payment (status: pending) + Transaction
   ↓
4. Redirects to payment provider or confirmation page
   ↓
5. After provider confirmation:
   GET /payment/{id}/success/?external_id=...&provider=stripe
   ↓
6. Updates Payment status to "completed"
   Marks Transaction as "completed"
   ↓
7. User sees success page

================================================================================
MODELS INTEGRATION
================================================================================

Payment Model:
  - user: ForeignKey(User)
  - amount: DecimalField
  - status: pending/completed/failed/cancelled
  - payment_provider: stripe/paypal/etc
  - external_payment_id: For provider reference
  - related_property: Optional property reference
  - related_rental: Optional rental reference
  - metadata: JSON for additional data
  - paid_at: Timestamp when completed

Transaction Model:
  - user: ForeignKey(User)
  - transaction_type: payment/refund/property_rental/platform_fee
  - amount: DecimalField
  - status: completed/failed/pending
  - reference: Auto-generated TRX-XXXXX
  - payment: ForeignKey(Payment) - Links transactions to payments
  - Auto timestamp fields

EXAMPLE USAGE

From Views:

  from .payment_utils import PaymentProcessor

  result = PaymentProcessor.process_rental_payment(
      user=request.user,
      student_property=property_obj,
      duration_months=6
  )

  if result['success']:
      payment = result['payment']
      print(f"Payment created: {payment.id}")
      print(f"Amount: ₦{result['total_amount']}")
      print(f"Platform Fee: ₦{result['platform_fee']}")

SUPPORT & TROUBLESHOOTING
================================================================================

Issue: Payment not created
→ Check if user is authenticated (@login_required)
→ Verify property exists and is valid
→ Check console for error messages with [v0] prefix

Issue: Transaction not linked to payment
→ Ensure payment creation completes before transaction
→ Check if payment object is returned correctly

Issue: Webhook not working
→ Verify webhook secret is correct
→ Check Stripe dashboard webhook events
→ Ensure URL is publicly accessible (not localhost)

Issue: Refund fails
→ Verify payment status is 'completed' before refunding
→ Check refund amount doesn't exceed payment amount
→ Verify payment record exists

For more details, see PAYMENT_SETUP.md
